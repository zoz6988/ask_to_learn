# Workflow Record: 20260530-003903

## Goal

Build a local web learning tool that combines uploaded learning materials with an AI question-answer-feedback loop. The tool should help users understand a book, textbook chapter, or paper through principle-focused questions and eventually produce a structured knowledge system.

## Initial Design

The requested architecture was:

```text
Provide material
-> AI asks questions
-> User answers
-> AI gives suggestions and corrections
-> Continue until understanding improves
-> AI generates a learning logic map
```

The implementation was scoped as a local web app instead of a hosted product:

- Frontend: plain HTML, CSS, JavaScript.
- Backend: Node.js built-in `http` server.
- AI API: Chat Completions-compatible endpoint.
- PDF handling: local text extraction.
- Logic map rendering: Python-generated PNG.

### 3. Improved PDF Extraction

The system `pdftotext.exe` came from MiKTeX and failed with:

```text
MiKTeX requires Windows 10 (or greater)
```

The extraction strategy was upgraded:

```text
pdfjs-dist
-> pypdf
-> pdftotext
```

This made complex PDF text extraction more reliable. If all methods fail, the app now tells the user the PDF is probably scanned or image-only.

### 4. Switched API Target To DeepSeek

The user asked to use the DeepSeek-compatible API pattern:

```python

    api_key="your-deepseek-api-key",
    base_url="https://api.deepseek.com"

```

The backend was changed from OpenAI Responses API to:

```text
POST /chat/completions
```

Default API base:

```text
https://api.deepseek.com
```

Default model:

```text

```

The page also gained editable API address and model fields.

### 5. Added Clear API Error Handling

Provider errors were normalized into clearer user-facing messages:

- Insufficient balance.
- Invalid API key.
- Unavailable model.
- Rate limit.

This made it easier to distinguish app bugs from account or provider issues.

### 6. Added Visual Progress Feedback

The user requested visible progress reminders for each analysis step.

Added a progress panel covering:

- Reading material.
- AI structure analysis.
- AI answer diagnosis.
- Logic map generation.
- Python PNG rendering.

The progress is estimated client-side, with stage labels and completion messages.

### 7. Refocused Questions On Principles

The user clarified the final learning goal:

> Understand principles and thinking, not data.

The prompts were updated so the AI avoids questions about:

- Exact accuracy.
- Sample size.
- Table values.
- Page numbers.
- Years.
- Author affiliations.

The AI now prioritizes:

- Why a method is designed this way.
- How a mechanism works.
- How concepts relate.
- How ideas transfer to new contexts.
- What boundaries and limitations exist.

### 8. Added Python Logic Map Rendering

The user wanted better visualization than text/Mermaid.

Added:

- `tools/render_logic_map.py`
- `public/generated/`
- `/api/render-map`

The final logic map flow became:

```text
AI returns structured JSON
-> Frontend sends map JSON to backend
-> Backend calls Python
-> Python renders a PNG with Pillow
-> Page displays and offers download
```

The rendered image includes:

- Core knowledge tree.
- Learning path.
- Argument or reasoning chain.
- Weak points for review.

## Known Limitations

- Scanned or image-only PDFs still require OCR before the app can learn from them.
- The progress bar is estimated, not based on provider-side token streaming.
- API calls depend on the provider account balance and model availability.
- Generated PNG layout is polished for concise structured maps; very long maps may need future pagination or zoomable canvas support.
- User progress is held in browser memory and resets on refresh.
